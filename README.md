## Как добавить фотографии

Ничего не переименовывай и не уменьшай — это делает скрипт.

**Шаг 1.** В папке проекта создай папку `inbox`, а в ней пять папок:

```
inbox/track/        → галерея «On-Track Action»
inbox/people/       → галерея «People & Moments»
inbox/atmosphere/   → галерея «Circuit & Atmosphere»
inbox/hero/         → кадр на первый экран главной (один файл)
inbox/portrait/     → портрет для страницы «Обо мне» (один файл)
```

**Шаг 2.** Перетащи туда фотографии **как есть**. Любые имена (`IMG_4821.jpg`
подойдёт), любой размер, хоть прямо из экспорта Lightroom в полном разрешении.

**Шаг 3.** Одна команда:

```bash
npm run photos
```

Она уменьшит кадры до 1600 px по длинной стороне, сожмёт с качеством 85,
впишет копирайт в метаданные, пронумерует и разложит по `src/photos/`.
В консоли будет видно, что с чем стало.

**Шаг 4.** Посмотреть, что получилось: `npm run dev` → http://localhost:4321/

**Шаг 5.** Опубликовать:

```bash
git add . && git commit -m "photos: Spa 2026" && git push
```

### Что полезно знать

- **Порядок кадров в галерее** — по времени съёмки, свежее сверху. Кроме раздела
  **People**: там порядок задан вручную, по силе кадров. Он живёт в файле
  `scripts/order.json` — это просто список имён твоих файлов из `inbox/people/`
  сверху вниз. Поменять местами две строки = поменять местами два кадра на сайте.
  Кадр, которого в списке нет, встаёт в конец галереи — так что новые снимки не
  ломают уже выстроенный порядок, но и наверх сами не попадут: впиши их в список
  или скажи мне.
- **Витрина на главной** — тоже ручной отбор, список `FEATURED` в
  `src/data/site.ts`. Если поменяешь порядок в `order.json`, кадры перенумеруются,
  и ссылки в `FEATURED` надо будет поправить — лучше скажи мне, я сделаю разом.
- **Описания для поисковиков** собираются из имён. Если файл называется
  `IMG_4821.jpg`, описание будет общим («On track»). Хочешь осмысленное —
  сложи кадры в подпапку с понятным именем, и оно пойдёт в описание:

  ```
  inbox/track/spa-2026-eau-rouge/IMG_4821.jpg  →  описание «Spa 2026 eau rouge»
  ```

  Это не обязательно, но помогает людям находить тебя через поиск по картинкам.
- **Папка `inbox/` в репозиторий не уходит** — твои оригиналы остаются только на
  твоём компьютере. На сайт публикуются уменьшенные копии.
- **Повторный запуск** пересобирает галереи из `inbox/` заново. Убрала кадр из
  `inbox` — он исчезнет и с сайта.

## Как поменять тексты

| Что | Где |
|---|---|
| Все надписи, названия галерей, meta-описания | `src/i18n/en.json` и `src/i18n/sr.json` |
| Контакты, список событий, техника, коллаборации | `src/data/site.ts` |
| Сколько кадров показывать на главной | `FEATURED_PER_GALLERY` в `src/data/site.ts` |
| Цвета, отступы, шрифт | `src/styles/global.css` |

Переименование галереи = поменять `title` в обоих JSON. Если нужно поменять и
адрес страницы (`/track/` → `/racing/`), то ещё: имя папки в `src/photos/`,
запись в `GALLERIES` (`src/data/site.ts`), ключи в обоих JSON и имена файлов
страниц в `src/pages/` и `src/pages/sr/`.

## Свой домен

Сайт живёт на **`naddians.photo`** (куплен 18 августа 2026 у Namecheap, $31.98 в год).
Это постоянный адрес — его и печатаем в заявках, подписях и QR-кодах.

Старый адрес `naddians.github.io` никуда не делся: GitHub сам перенаправляет с него
на новый, так что уже напечатанные ссылки продолжают работать.

Домен `naddians.photos` куплен как защита от опечатки. Отдельного сайта на нём нет —
он перенаправляется на основной адрес настройками у регистратора.

Что задаёт адрес сайта в проекте:

1. `site` в `astro.config.mjs` — от него строятся все внутренние ссылки, canonical
   и hreflang;
2. адрес карты сайта в `public/robots.txt`;
3. файл `public/CNAME` — по нему GitHub Pages понимает, на каком домене мы живём.

Одна тонкость на будущее: сайт публикуется через GitHub Actions, а в этом режиме
файл `CNAME` из собранного сайта домен сам **не прописывает** — так работает только
старый способ публикации из ветки. Домен пришлось один раз задать в настройках
репозитория (Settings → Pages → Custom domain); дальше `CNAME` его удерживает,
и без этого файла настройка слетает при каждой публикации.

Менять эти три места нужно только при следующем переезде. DNS-записи домена
(четыре `A`, четыре `AAAA` и `www`) прописаны у регистратора и указывают на GitHub.
